1. Architecture Overview & Technology Stack

This project is a multi-branch retail & inventory management enterprise backend service engineered to withstand high-concurrency race conditions, prevent financial floating-point rounding errors, enforce branch-level data isolation, and guarantee absolute auditability.

Core Architectural Highlights
  • Strict MVC Layering: Separation of HTTP handling (Controllers), Business transactions & validation (Services), Database queries (Repositories), and Entities (Models).
  • PostgreSQL Engine Constraints: Native CHECK constraints (quantity >= 0, price_paise >= 0) and compound unique keys ((branch_id, product_id), (branch_id, email)) ensure integrity at the database engine level.
  • Concurrency Control: SELECT ... FOR UPDATE pessimistic row-level locking with deterministic lexicographical product sorting eliminates deadlocks and overselling.
  • Monetary Precision: All financial calculations are stored and calculated in integer paise (1 INR = 100 paise). Floating-point math is completely eliminated.
  • Defense-in-Depth Authentication: Access tokens (15m expiration) + Refresh tokens stored as SHA-256 hashes with atomic single-use rotation. Replay attacks trigger immediate family-wide session invalidation.

6. Engineering Trade-offs Summary

  • Pessimistic Locking vs Optimistic Locking: In inventory reservation, optimistic concurrency results in high abort/retry rates during flash sales. Pessimistic SELECT ... FOR UPDATE serializes access per SKU, eliminating wasted work.
  • Deterministic Lock Ordering: Multi-item orders sort product IDs lexicographically before locking, mathematically eliminating lock-inversion deadlocks.
  • Integer Paise Currency: IEEE 754 floating-point errors are eliminated by storing all currency as 32-bit integers in minor currency units (paise).
